## 固定比较

R00/R01 为常规 global MLP 控制，R10/R11 为 residual TPP L124；第二位表示 global-only SupCon。均为 amplitude-only，同一 256 维表征，1,878,142 个参数。182 个公共 state tensor 的初始化完全相同；同池化下 CE/SupCon 的全部初始 tensor 完全相同。历史 H/Y 与 pseudo-Tx 切片均保持原样。

每 run 200 epoch，每 epoch 300 次更新，batch=16。每个 batch 两个源环境各八条，均覆盖六类，批内样本不重复。采样随机数独立于模型和执行顺序；epoch 代表固定更新数，而非对全部源样本恰好遍历一次。

Adam，初始学习率 0.001，无 weight decay，连续衰减 `0.001 × 0.9^(step/10000)`。SupCon temperature=0.2，固定 λ=0.025，6000 步线性 warm-up。四臂均 **不进行新的超参数搜索**；λ沿用 Y 曾经通过源数据选择的值。这是固定强度的因素比较，不宣称确定任何方法的最优超参数。

checkpoint 按 1200 条源验证样本的 macro-F1 选择，平局取最早。4800 条源训练与源验证的 subject/acquisition 均隔离。所有 R source run 完整结束并通过检查之前，不允许 R 目标评估；缺少源结果时 evaluator 拒绝执行的实际负向检查已保存。

## 中断恢复与检查范围

每个 epoch 将模型、Adam 状态、CPU/CUDA/Python/NumPy RNG、完整历史以及截至当时的最佳源模型与预测一起写入临时文件，再原子替换，并以带哈希的 progress 指针提交。外部中断后从最后提交 epoch 重放；数值或哈希失败停止队列，保留失败记录，不静默剔除 run。

恢复时逐项核对权重、优化器及 RNG 精确一致。已用实际 E1 源数据执行 R11 的 2 epoch × 4 步 CPU 对照：连续执行与第一个 epoch 后中断恢复的全部最终参数差为零，1200 条源预测一致。另从实际 CUDA checkpoint 恢复，权重、Adam 状态和 RNG 均精确一致。

两次先行 CUDA 轨迹检查的参数阈值未通过，完整证据保留在运行根目录 `qa/resume_v1` 与 `qa/resume_v2_cublas`。独立重复的第一 epoch 在中断前已有参数差异；两次检查的源预测均一致。新增 cuBLAS 工作区设置仍未消除全部差异。当前 PyTorch 2.6.0+cu124 的 adaptive-max-pool CUDA backward 不支持严格确定性，因此这些检查不能给出 CUDA 长轨迹逐位一致的承诺；没有为通过检查修改原池化算法或放宽参数阈值。CPU 轨迹与 CUDA 状态恢复是分别验证的。

连续运行通常保留 epoch 1、每十个 epoch、最近两个 epoch 及源选择的最佳 checkpoint，供恢复和后续机制诊断。恢复入口只清理继续运行后新近越过的当前 run 文件，不回扫或删除中断前更早的已提交边界快照；因此恢复过的 E1_R00_401 另外保留 `resume_epoch_0094.pt`，未中断的 E1_R01_401 和 E1_R10_401 则各自精确保留预定的 22 个节点。该额外快照不改变更新数、checkpoint 选择或发布结果；紧凑发布包仍只索引 source-best checkpoint。运行资源计数随实际结果保存。
